# 1주차 젠스파크 기존 PPT 변경 요청 프롬프트

아래 프롬프트는 **이미 생성된 1주차 PPT를 젠스파크에 다시 업로드한 뒤** 사용한다. 새 PPT 제작 요청이 아니다.

1. 기존에 젠스파크로 생성한 1주차 PPTX
2. `week01.zip`

- `04_학생파일_배포수령_가이드.md`

## 복사해 사용할 변경 프롬프트

```text
첨부한 기존 1주차 PPT를 수정해 주세요. 이 요청은 새 프레젠테이션 제작이 아니라 기존 장표에 학생 활동 구간을 삽입하고 부족한 안내를 교체하는 수정 작업입니다.

[1. 반드시 유지할 것]
- 기존 PPT의 디자인 테마, 마스터, 폰트, 색상, 푸터, 페이지 표시 방식을 유지하세요.
- 기존의 ‘중고 노트북 가격 예측’ 체험과 ‘방금 모델을 공부한 것이 아니라 서비스를 사용했습니다’라는 흐름을 유지하세요.
- 기존 AWS 실습 장표와 `screens` 폴더의 실제 AWS 화면을 유지하세요. 스크린샷을 그림으로 다시 만들지 마세요.
- 기존 장표를 전체적으로 새로 작성하지 마세요. 중복되거나 잘못된 장표만 수정하세요.

[2. 기존 도입부 직후에 추가할 구간]
기존의 중고 노트북 가격 예측 시연과 과목 정의 장표 뒤, AWS 개념 설명 전에 아래 순서로 학생 활동 구간을 삽입하세요.

A. 15주 프로젝트 로드맵 — 3장
1) 15주 뒤 완성할 것: 데이터 → 모델 → API → AWS 배포 → 자동 배포 → 모니터링
2) M1·M2·M3·M4 마일스톤: 4주 재현 가능한 모델, 8주 접속 가능한 URL, 13주 운영 가능한 서비스, 15주 최종 시연
3) 개인별로 남길 증거: 커밋, 시연, 리뷰·테스트, 문제 해결 기록

B. 학생 파일 받기 — 4장
1) 오늘 받을 파일: `cloud-mlops-team-start-kit-v1.zip`
2) 받는 곳과 압축 해제: LMS `1주차 → 팀빌딩 자료`, 작업 경로 `~/cloud-mlops/team-project/`
3) 시작 전 확인: `bash verify.sh`, 정상 출력 `READY: team-start-kit`
4) 수정·제출 파일: `TEAM_REGISTRATION.md`, `TEAM_CHARTER.md`, `ROLE_ROTATION.csv`, `PROJECT_IDEA_CARD.md`
실제 ZIP에 없는 파일이나 LMS·S3·Git URL을 임의로 만들지 마세요.

C. 학생 주도 팀빌딩·주제선정 — `09_학생주도_팀빌딩_주제선정_활동교안.md` 기준 33장
장표를 강사 설명용 문장으로 줄이지 말고, 학생이 실제로 이동·협상·채점·교환 검토하고 파일을 작성하는 활동 장표로 만드세요.
- 개인 역량 여권 작성과 30초 소개
- 후보 팀 경험·희망 역할 비교
- 답장·결정·지각·충돌 규칙 협상
- 역할 1순위 중복 해소와 역할 순환 합의
- 주제 후보 3개 개인 독립 채점
- 팀 후보 2개 선정
- 옆 팀과 후보 카드를 바꾸어 공격 질문 8개 수행
- 피드백을 반영한 후보 수정과 30초 공개 설명
- 4명 권장, 남는 인원은 3명 팀
- Python·화면·AWS·문서 경험이 한쪽에 몰리지 않게 구성
- 제품·데이터, 모델·실험, 플랫폼·배포, 운영·품질 역할
- 4·8·12주 종료 후 역할 순환
- 팀 규칙, 팀 이름, GitHub·AWS 이름 규칙
- 결석·역할 편중·중도 이탈·충돌 처리
- 마지막에 팀 파일 6개를 LMS에 제출하는 체크리스트

D. 실습 프로젝트 예시 주제 참고 — 7장
`07_실습프로젝트_예시주제_학생가이드.md`를 기준으로 하세요.
1) 자유 주제를 짜내는 것이 아니라 15주 안에 완성 가능한 후보를 고른다는 안내
2) 서울 자전거 대여량 예측
3) 건물 난방·냉방 부하 예측
4) 설비 고장 가능성 판별
5) 추가 후보: 강의실 사용 여부, 전력 사용량, 콩 품종, 콘크리트 강도
6) 추가 후보: 온라인 구매 세션과 선택하지 않는 고위험 주제
7) 10점 점수표로 8점 이상인 후보 2개를 `PROJECT_IDEA_CARD.md`에 작성하는 활동

예시 주제 장표는 모델 이름만 나열하지 말고, 각 주제를 `사용자 → 입력 → 예측 결과 → 사용자 화면 → 운영 메특`으로 보여 주세요. 각 데이터셋의 UCI 공식 링크를 해당 장표 또는 발표자 노트에 남기세요.

[3. 기존 AWS 실습과 연결]
- 새로 추가한 학생 활동 구간 뒤에 기존 AWS 로그인·서울 리전·S3·CloudShell 실습 장표를 이어 붙이세요.
- 전환 장표의 메시지는 ‘이제 팀의 첫 공용 작업 공간을 AWS에 만듭니다’로 작성하세요.
- AWS 화면마다 콘솔 이동 경로, 확인할 값, 실수하기 쉬운 부분, AWS 공식 문서 링크를 유지하세요.
- 가짜 AWS 콘솔 화면이나 임의의 계정 ID·버킷 이름·리소스 ID를 만들지 마세요.

[4. 시간 구성]
230분 수업을 아래 범위로 맞추세요. 시간은 발표자 노트에 넣고 학생 화면에 반복 표시하지 마세요.
- 예측 서비스 체험과 과목 소개: 20분
- 15주 로드맵과 파일 준비: 20분
- 개인 역량 여권·팀 구성 협상: 55분
- 주제 후보 독립 채점·팀 합의: 45분
- 다른 팀 공격 검토·후보 수정: 40분
- AWS 로그인·서울 리전·S3 빠른 성공: 35분
- 제출 확인·비용·리소스 정리·마무리: 10~15분

[5. 표현과 편집 규칙]
- 대상은 클라우드·MLOps를 처음 배우는 학생입니다.
- 학생에게 직접 말하는 쉽고 자연스러운 한국어를 사용하세요.
- ‘여러분은 이미 모델을 만들어 보셨죠’, ‘왜 아무도 못 쓸까요’ 같이 학생 경험을 임의로 가정하는 질문은 사용하지 마세요.
- 한 장에는 하나의 행동이나 메시지만 담으세요. 작은 글자로 표를 박아 넣지 마세요.
- 활동 장표에는 ‘지금 할 일’, ‘작성할 파일’, ‘정상 결과’, ‘제출할 것’이 시각적으로 구분되게 하세요.
- 학생용 본문에 제작 메모·프롬프트·NCS 코드를 노출하지 마세요.

[6. 완료 전 검수]
- 기존 디자인과 AWS 실습 장표가 유지됐는지 확인하세요.
- 팀 구성 인원, 역할 순환, 개인 증거, 결석·이탈 처리가 보이는지 확인하세요.
- 개인 역량 여권, 팀 협상판, 후보 독립 채점, 다른 팀 공격 검토가 각각 별도 활동 장표로 보이는지 확인하세요.
- 학생이 팀 ZIP을 어디서 받고, 어디에 풀고, 무엇을 수정·제출하는지 알 수 있는지 확인하세요.
- 예시 주제 8개, 우선 추천 3개, 8점 선정 기준이 보이는지 확인하세요.
- 1주차에는 후보 2개만 선택하고 3주차 데이터 검증 후 1개를 확정한다는 절차가 보이는지 확인하세요.
- AWS 화면의 순서·가독성·출처·민감정보 노출 여부를 확인하세요.

완료본은 기존 파일을 덮어쓰지 말고 `클라우드MLOps_01주차_학생활동추가_수정본.pptx`로 내보내세요.
```
