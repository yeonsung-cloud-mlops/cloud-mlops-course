### 2-1. MLOps란 무엇인가 (10분)

**강의 스크립트**
> 질문부터 하나 드리겠습니다. 여러분이 지난 학기에 만든 정확도 92% 모델, 그걸 지금 친구 노트북에서 돌리려면 뭐가 필요할까요?
> (학생 답 유도 — 파이썬, 라이브러리, 데이터 …)
> 네, 파이썬 버전 맞춰야 하고, 라이브러리 버전 맞춰야 하고, 데이터 경로 맞춰야 하고, 그러고도 "저는 안 되는데요" 소리가 나옵니다. 이 상황을 한 문장으로 "**제 컴퓨터에선 되는데요**" 문제라고 부릅니다.
>
> MLOps는 여기서 나온 말입니다. ML(머신러닝) + Ops(Operations, 운영). 우리말로 하면 **"머신러닝 모델을 실제로 굴리기 위한 운영 기술"** 정도입니다.
> 그런데 이걸 개념으로 외우면 하나도 안 남습니다. 그래서 저는 이렇게 정의하겠습니다.
> **MLOps = 모델이 노트북을 떠나 다른 사람 손에 닿기까지 필요한 모든 잡일을 자동화하는 것.**
>
> 비유를 하나 들겠습니다. 요리로 치면 이렇습니다. 여러분이 지금까지 배운 머신러닝은 **"맛있는 요리를 한 접시 만드는 법"**입니다. MLOps는 **"그 요리를 식당에서 하루 300그릇 파는 법"**입니다.
> 한 접시 만드는 거랑 300그릇 파는 건 완전히 다른 문제죠. 재료를 어디서 매일 받을지(데이터 파이프라인), 레시피를 어떻게 기록할지(실험 관리), 주방을 어떻게 똑같이 복제할지(컨테이너), 손님 주문을 어떻게 받을지(API), 오늘 몇 그릇 나갔고 불만은 없었는지(모니터링). 이게 전부 MLOps입니다.
>
> 하나만 더. 실무에서 데이터 과학자가 시간을 어디에 제일 많이 쓸까요? 모델 튜닝? 아닙니다. **데이터 준비와 운영**에 대부분을 씁니다. 모델 코드는 전체 시스템에서 아주 작은 조각입니다. 여러분이 이번 학기에 체감하게 될 겁니다.

**판서/슬라이드 요점**
- MLOps = ML + Operations. "노트북을 떠난 모델을 굴리는 기술"
- 핵심 문제 3개: ① 제 컴퓨터에선 되는데요 ② 3주 전 그 결과 어떻게 냈지 ③ 어제까진 잘 됐는데
- 모델 코드는 전체 시스템의 일부일 뿐 — 나머지가 전부 MLOps 영역
- 이 과목의 평가 기준은 **정확도가 아니라 "끝까지 도는가"**

**학생 질문 예상 & 답변**
- Q: DevOps랑 뭐가 다른가요? → A: DevOps는 코드만 다룹니다. MLOps는 코드 + **데이터 + 모델**을 같이 다룹니다. 데이터가 바뀌면 결과가 바뀌기 때문에 훨씬 까다롭습니다.
- Q: 이거 취업에 도움 되나요? → A: 채용 공고에 "MLOps 엔지니어"라는 직무가 따로 있습니다. 그리고 신입 데이터 분석가도 요즘은 "본인이 만든 모델을 API로 띄워봤나"를 묻습니다. 여러분 14주차 결과물이 그 답이 됩니다.

### 2-2. 14주 로드맵 한 장 (10분)

**강의 스크립트**
> 이제 지도를 한 장 보여드리겠습니다. 이 그림은 앞으로 **매주 첫 슬라이드에 다시 나옵니다.** 매주 "우리 지금 여기입니다" 하고 위치를 찍어드릴 겁니다. 길을 잃었다 싶으면 이 그림만 보세요.

```
[1주] 계정·저장소        [2주] 서버 환경
   AWS 로그인 · S3          EC2 · 리눅스 · Python
        │                        │
        └────────┬───────────────┘
                 ▼
```

> 그러니까 **1주차를 빼먹으면 3주차가 안 됩니다.** 오늘 만드는 버킷 이름을 꼭 적어두세요.

**판서/슬라이드 요점**
- 1~2주 = 도구 준비 / 3~5주 = 데이터·모델 / 6~8주 = 패키징·서빙 / 9~10주 = 관리형 서비스 체험 / 11~12주 = 자동화·운영 / 13~14주 = 마무리
- 마일스톤 4개: M1(4주) M2(8주) M3(12주) M4(14주)
- 팀 프로젝트 총 공수 18~20시간 (수업 내 12h + 팀 자율 6~8h)
- **오늘 만드는 S3 버킷이 학기 내내 쓰인다**

**학생 질문 예상 & 답변**
- Q: 중간에 한 주 결석하면 따라갈 수 있나요? → A: 됩니다. 회차마다 **완성본 저장소 태그**(`week-01-done` 형식)를 드립니다. 결석한 주는 완성본에서 이어받으면 됩니다. 다만 그 주 체크포인트 점수는 못 드립니다.
- Q: 딥러닝은 안 하나요? → A: 이 과목에서는 CPU로 10분 안에 학습되는 모델만 다룹니다. 딥러닝을 배우는 과목이 아니라 **모델을 서비스로 만드는 과목**이기 때문입니다.

### 2-3. 클라우드 기본 개념 (10분)

**강의 스크립트**
> 마지막 10분은 클라우드 용어 네 개만 잡고 갑니다. 이것만 알면 오늘 실습은 됩니다.
>
> 첫째, **리전(Region)**. 우리말로 "지역"입니다. AWS 컴퓨터들이 실제로 놓여 있는 지구상의 위치입니다. 서울에도 있고, 도쿄에도 있고, 미국 버지니아에도 있습니다.
> 여기서 중요한 것 — **리전이 다르면 완전히 다른 세상입니다.** 서울 리전에 만든 서버는 버지니아 리전 화면에서는 **안 보입니다.** 없어진 게 아니라 다른 방에 있는 겁니다.
> 매년 이걸로 사고가 납니다. 콘솔 오른쪽 위에 지역 이름이 뜨는데, 기본값이 버지니아인 경우가 있어요. 그 상태로 서버를 만들고 다음 주에 "제 서버가 사라졌어요" 합니다.
> 그래서 우리는 **한 학기 내내 서울, `ap-northeast-2` 하나만 씁니다.** 실습 A에서 제일 먼저 할 일이 이걸 고정하는 겁니다.
>
> 둘째, **가용영역(Availability Zone, AZ)**. 리전 안에 있는 실제 건물, 즉 데이터센터입니다. 서울 리전 안에 네 개쯤 있습니다. 왜 나눠놨을까요? 건물 하나에 불이 나거나 정전되도 나머지가 살아있게 하려고요. 우리 수업에서는 크게 신경 쓸 일이 없습니다. "리전 안에 건물이 여러 개 있구나" 정도만.
>
> 셋째, **온디맨드(On-Demand)**. "쓴 만큼 낸다"는 뜻입니다. 서버를 켜둔 시간만큼 초 단위로 과금됩니다. 이게 클라우드의 핵심이자 여러분이 조심해야 할 이유입니다.
> 비유하면 **호텔방**입니다. 집을 사는 게 아니라 방을 빌리는 겁니다. 체크아웃을 안 하면 계속 요금이 붙습니다. **인스턴스 Stop이 체크아웃입니다.**
> 하나 더. 서버를 껐어도 **저장장치(EBS) 요금은 계속 나갑니다.** 호텔로 치면 방은 비웠는데 짐 보관함은 계속 빌리고 있는 셈입니다. 그래서 학기 말에는 아예 삭제까지 합니다.
>
> 넷째, **책임 공유 모델(Shared Responsibility Model)**. AWS가 어디까지 책임지고 우리가 어디부터 책임지는지를 나눈 겁니다.
> AWS는 **"클라우드 자체의 보안"**, 즉 건물, 전기, 하드웨어, 네트워크 선을 책임집니다. 우리는 **"클라우드 안에서의 보안"**, 즉 비밀번호를 어떻게 관리하는지, 어떤 포트를 열어놨는지, 데이터를 아무나 볼 수 있게 해뒀는지를 책임집니다.
> 오늘 MFA를 설정하는 게 바로 우리 쪽 책임입니다. 비밀번호 하나 털리면 남이 여러분 계정으로 GPU 서버 100대를 켤 수 있습니다. 실제로 벌어지는 일입니다.

**판서/슬라이드 요점**
- **리전** = 지구상 위치. 우리는 `ap-northeast-2`(서울) 고정. 리전 다르면 리소스가 안 보인다
- **가용영역(AZ)** = 리전 안의 데이터센터 건물
- **온디맨드** = 호텔방. 켜둔 만큼 과금. Stop = 체크아웃. 단 **EBS(짐 보관함)는 계속 과금**
- **책임 공유 모델** = AWS는 건물·전기·하드웨어, 우리는 비밀번호·권한·포트
- 오늘 우리가 지는 책임: **MFA 켜기**

**학생 질문 예상 & 답변**
- Q: 왜 하필 서울인가요? 미국이 더 싸지 않나요? → A: 조금 쌉니다. 하지만 거리가 멀면 응답이 느리고, 무엇보다 **전원이 같은 리전을 봐야 서로 도와줄 수 있습니다.** 리전 섞이면 트러블슈팅이 지옥이 됩니다.
- Q: 리전을 바꾸면 지금까지 만든 게 지워지나요? → A: 아니요, 안 지워집니다. **안 보일 뿐**입니다. 서울로 돌아오면 그대로 있습니다.
- Q: S3 버킷도 리전이 있나요? → A: 있습니다. 버킷은 만들 때 리전을 정하고 나중에 못 바꿉니다. 이름은 전 세계에서 유일해야 하지만, 실제 데이터는 특정 리전에 놓입니다.

## 3. 실습 A — AWS 콘솔 로그인 · MFA · 리전 고정 · 권한/예산 확인 (45분) · 공통 예제 따라하기

**목표** 본인 IAM 계정으로 콘솔에 로그인하고, MFA를 켜고, 리전을 서울로 고정한 뒤, 내 권한과 예산 알람이 살아있는지 눈으로 확인한다.

**사전 배포 파일**
- `01_계정정보.txt` — 개인별로 다르게 배포. 내용 예시:
```text
AWS 계정 ID(별칭) : yonsei-mlops
IAM 사용자 이름   : mlops-2026-<학번>
초기 비밀번호     : (개별 배포)
콘솔 로그인 URL   : https://yonsei-mlops.signin.aws.amazon.com/console
고정 리전         : ap-northeast-2 (아시아 태평양(서울))
```
- `01_MFA설치안내.pdf` — 인증 앱 3종 설치 방법 + 앱 설치 불가 시 대안

> ⚠ **강사 운영 팁**: 시작 전에 칠판에 로그인 URL을 **크게** 적어둔다.
> "aws.amazon.com에서 로그인" 하려는 학생이 반드시 나오는데, 그건 **루트 계정 로그인 화면**이라 우리 계정으로는 못 들어간다. 반드시 위 전용 URL을 쓰게 한다.

### 수행 순서

**① 콘솔 로그인 (10분)**

1. 브라우저는 **Chrome 또는 Edge**를 쓴다. 시크릿 모드/프라이빗 창을 권장한다(다른 AWS 계정 세션과 섞이는 사고 방지).
2. 주소창에 배포받은 로그인 URL을 그대로 입력한다.
```text
https://yonsei-mlops.signin.aws.amazon.com/console
```
3. `IAM 사용자 이름`에 `mlops-2026-<학번>`, `암호`에 초기 비밀번호를 입력한다. (`<학번>`은 본인 학번 8자리)
4. 최초 로그인이면 **비밀번호 변경 화면**이 뜬다. 새 비밀번호를 정하고 **반드시 메모**한다.
   - 조건: 8자 이상, 대문자·소문자·숫자·특수문자 각 1개 이상
   - 권장 형식 예: `Mlops!<학번뒤4자리>2026`
- 확인 포인트: 오른쪽 위에 `mlops-2026-<학번> @ yonsei-mlops` 라고 뜨면 성공.

**② 리전을 서울로 고정 (5분)**

1. 콘솔 오른쪽 위, 계정 이름 왼쪽에 있는 **지역 선택 메뉴**를 클릭한다.
2. 목록에서 **`아시아 태평양(서울) ap-northeast-2`** 를 선택한다.
3. 주소창 URL에 `region=ap-northeast-2` 가 들어있는지 눈으로 확인한다.
4. 이 상태에서 **브라우저 북마크로 저장**한다. 이름은 `AWS-서울`.
- 확인 포인트: 오른쪽 위에 "서울"이라고 한글로 표시된다. 매 수업 시작 시 이걸 먼저 본다.

> ⚠ 리전 표시가 "버지니아 북부" 또는 "N. Virginia"이면 **지금 하는 모든 작업이 헛수고**다. 옆 사람 것도 서로 봐준다.

**③ MFA(다단계 인증) 설정 (15분)**

> MFA(Multi-Factor Authentication, 다단계 인증) = 비밀번호에 더해 **1분마다 바뀌는 6자리 숫자**를 하나 더 요구하는 잠금장치.

1. 스마트폰 앱스토어에서 인증 앱을 설치한다. 셋 중 아무거나.
   - Google Authenticator / Microsoft Authenticator / Twilio Authy
2. 콘솔 오른쪽 위 **계정 이름 클릭 → 보안 자격 증명(Security credentials)** 으로 들어간다.
3. **다단계 인증(MFA)** 섹션에서 **MFA 디바이스 할당**을 누른다.
4. 디바이스 이름에 `phone-<학번>` 을 입력하고, **인증 관리자 앱(Authenticator app)** 을 선택한 뒤 다음.
5. 화면에 QR 코드가 뜬다. 폰의 인증 앱에서 `+` → **QR 코드 스캔**으로 찍는다.
6. 앱에 6자리 숫자가 뜨기 시작한다. **연속된 두 개**를 입력한다.
   - 첫 번째 코드 입력 → 숫자가 바뀔 때까지 기다림 → 두 번째 코드 입력
7. **MFA 추가** 클릭.
8. 로그아웃 후 다시 로그인해서 6자리 코드를 요구하는지 확인한다.
- 확인 포인트: 보안 자격 증명 화면의 MFA 목록에 `phone-<학번>` 이 나타나면 성공. **이 화면을 캡처**한다. (체크포인트 제출물 3번)

> ⚠ **폰에 앱을 못 깔면** (앱스토어 로그인 불가, 저장공간 부족 등)
> → Chrome 확장 프로그램 방식의 인증기 또는 강사 예비 기기를 사용한다.
> → 그래도 안 되면 **오늘은 MFA 미설정으로 넘어가고 다음 주 시작 전까지 해결**한다. 조교가 명단에 기록한다. MFA 때문에 오늘 실습 전체가 멈추면 안 된다.

**④ 내 IAM 권한 확인 (8분)**

1. 검색창에 `IAM` 입력 → IAM 서비스로 이동.
2. 왼쪽 메뉴 **사용자(Users)** → 본인 이름 `mlops-2026-<학번>` 클릭.
3. **권한(Permissions)** 탭에서 연결된 정책 이름을 확인한다. (예: `MLOpsStudentPolicy`)
4. 정책을 펼쳐 다음 두 가지를 눈으로 찾는다.
   - 허용 서비스 목록: `s3`, `ec2`, `ecr`, `cloudwatch`, `sagemaker`, `bedrock`
   - 조건절의 인스턴스 타입 화이트리스트: `t3.micro`, `t3.small`, `t3.medium`
- 확인 포인트: "GPU 인스턴스는 아예 신청이 거부되도록 되어 있다"는 것을 본인 눈으로 확인.

**강의 스크립트 (이 단계에서 붙이는 설명)**
> 지금 보고 계신 게 **IAM 정책**입니다. "이 사람은 뭘 해도 되고 뭘 하면 안 되는가"를 적어놓은 규칙표입니다.
> 아파트 출입카드 같은 겁니다. 여러분 카드는 우리 동, 우리 층만 열립니다. 옥상 기계실은 안 열립니다. 여기서 `t3.medium`까지만 허용된 게 그 기계실 잠금이라고 보시면 됩니다.
> 실습하다가 "AccessDenied"라는 빨간 글씨가 뜨면 여러분이 뭘 잘못 친 게 아니라 **권한이 없는 겁니다.** 그때는 저를 부르세요.

**⑤ Budgets 예산 알람 확인 (7분)**

1. 콘솔 검색창에 `Billing and Cost Management` 입력 → 이동.
2. 왼쪽 메뉴에서 **Budgets(예산)** 클릭.
3. 본인 예산 `mlops-2026-<학번>-monthly` 를 찾아 클릭한다.
4. 다음 세 가지를 확인한다.
   - 예산 금액: **$10 / 월**
   - 알림 임계값: **50% / 80% / 100%**
   - 수신 이메일: 본인 학교 메일 주소가 맞는가
5. 메일 주소가 틀렸으면 손을 든다. (학생 권한으로는 수정 불가 — 강사가 처리)
- 확인 포인트: 현재 사용액이 $0.00 ~ $0.5 사이면 정상.

> ⚠ Billing 화면은 IAM 사용자에게 기본적으로 안 보인다. 강사가 사전에 계정 설정에서 **IAM 사용자 결제 정보 액세스**를 활성화하고 `aws-portal:ViewBilling` 권한을 부여해 두어야 한다. 안 보이면 강사 화면으로 대신 보여주고 넘어간다.

### ⚠ 여기서 막히면

| 증상 | 원인 | 조치 |

### 컷오프 안내

실습 B(S3)는 MFA 없이도 진행 가능하므로, **MFA 때문에 반 전체를 세우지 않는다.**

## 4. 실습 B — 개인 S3 버킷 만들고 CLI로 다루기 (60분) · 각자 직접 수행

**목표** 본인 이름의 S3 버킷을 만들고 표준 폴더 구조를 세운 뒤, 콘솔과 CloudShell CLI 두 가지 방법으로 같은 파일 업로드/다운로드를 해본다.

**과제 지시문** (학생에게 그대로 읽어줄 문장)

> 지금부터 60분 동안 여러분 이름이 붙은 **개인 저장소**를 하나 만듭니다.
> 이 저장소는 오늘 만들고 끝나는 게 아니라 **14주 내내 씁니다.** 3주차 데이터도 여기 들어가고, 4주차 모델 파일도 여기 들어가고, 12주차 로그도 여기를 봅니다.
> 그래서 **폴더 이름을 제가 정해드리는 대로** 똑같이 만들어야 합니다. 여러분 마음대로 만들면 제가 나눠드리는 스크립트가 안 돌아갑니다.
> 그리고 같은 작업을 **두 번** 합니다. 한 번은 마우스로 클릭해서, 한 번은 검은 화면에 명령어를 쳐서. 왜 두 번 하냐면, 앞으로 12주 동안 여러분이 쓰게 될 건 **마우스가 아니라 명령어**이기 때문입니다. 오늘 손에 익혀둡시다.

### 수행 항목

**1. S3 버킷 생성 (10분)**

1. 콘솔 검색창에 `S3` → S3 서비스로 이동.
2. **버킷 만들기(Create bucket)** 클릭.
3. 항목을 다음과 같이 정확히 입력한다.

| 항목 | 값 |
|---|---|
| AWS 리전 | **아시아 태평양(서울) ap-northeast-2** |
| 버킷 이름 | `mlops-2026-<학번>` (예: 학번이 20231234면 `mlops-2026-20231234`) |
| 객체 소유권 | ACL 비활성화됨 (기본값 유지) |
| 퍼블릭 액세스 차단 | **모든 퍼블릭 액세스 차단 — 체크 유지** |
| 버킷 버전 관리 | 비활성화 (기본값) |
| 기본 암호화 | SSE-S3 (기본값) |

4. **태그** 항목에서 다음 3개를 추가한다. (비용 추적용 — 필수)

| 키 | 값 |
|---|---|
| `Course` | `MLOps` |
| `Team` | `T00` (팀 미정이므로 임시. 3주차에 수정) |
| `Owner` | `<학번>` |

5. **버킷 만들기** 클릭.
- 확인 포인트: 버킷 목록에 `mlops-2026-<학번>` 이 보이고, AWS 리전 열이 `아시아 태평양(서울) ap-northeast-2` 이면 성공.

> ⚠ **버킷 이름은 전 세계에서 유일해야 한다.** 지구상 모든 AWS 사용자가 같은 이름 공간을 쓴다.
> `mlops` 나 `test-bucket` 같은 이름은 100% 실패한다. 반드시 `mlops-2026-<본인 학번>` 형식을 지킨다.
> 소문자·숫자·하이픈만 되고, 대문자와 밑줄(`_`)은 못 쓴다.

**2. 표준 폴더 구조 만들기 (10분)**

1. 방금 만든 버킷을 클릭해 들어간다.
2. **폴더 만들기(Create folder)** 로 다음 3개를 만든다. 이름을 정확히 지킨다.

| 폴더 | 용도 | 규칙 |
|---|---|---|
| `raw/` | 받은 그대로의 원본 데이터 | **절대 수정·삭제 금지** |
| `processed/` | 전처리를 마친 데이터 | 스크립트로만 생성 |
| `models/` | 학습된 모델 파일 | 4주차부터 사용 |

- 확인 포인트: 버킷 안에 세 폴더가 보이면 성공.

**강의 스크립트 (이 단계에서 붙이는 설명)**
> 왜 이렇게 나누냐고요? 3주차에 자세히 하겠지만 한 줄만 미리 말씀드립니다.
> **`raw/`는 성역입니다.** 원본은 절대 손대지 않습니다. 원본을 고쳐버리면 "어? 아까랑 결과가 다른데?" 하는 순간 되돌릴 방법이 없습니다.
> 원본은 그대로 두고, 가공한 결과를 `processed/`에 새로 씁니다. 그러면 스크립트를 다시 돌리기만 하면 언제든 같은 결과가 나옵니다. 이걸 **재현성**이라고 하고, 이 과목이 처음부터 끝까지 미는 가치입니다.

**3. 콘솔에서 업로드/다운로드 (10분)**

1. 강사가 배포한 `sample_bike.csv` 를 노트북에 저장한다.
2. `raw/` 폴더로 들어가 **업로드(Upload)** → 파일 추가 → `sample_bike.csv` 선택 → **업로드**.
3. 업로드된 파일을 클릭해 **객체 URL**과 **S3 URI**를 확인한다. S3 URI는 이런 모양이다.
```text
s3://mlops-2026-<학번>/raw/sample_bike.csv
```
4. **다운로드** 버튼을 눌러 다시 받아본다.
5. 객체 URL을 새 탭에 붙여넣어 본다. → **AccessDenied**가 뜬다.
- 확인 포인트: 마지막 단계에서 AccessDenied가 뜨는 게 **정상**이다. 퍼블릭 액세스를 차단해뒀기 때문. "인터넷에 있다고 아무나 볼 수 있는 게 아니다"를 여기서 짚는다.

**4. CloudShell에서 CLI로 같은 작업 반복 (25분)**

> CloudShell = AWS가 브라우저 안에서 띄워주는 리눅스 터미널. 설치할 게 없고 내 권한이 이미 적용되어 있다.

1. 콘솔 오른쪽 위 **`>_` 아이콘**(CloudShell)을 클릭한다. 검은 창이 열릴 때까지 30초~1분 기다린다.
2. 먼저 내가 누구인지 확인한다.
```bash
aws sts get-caller-identity
```
출력에 `"Arn": "arn:aws:iam::...:user/mlops-2026-<학번>"` 이 보이면 정상.

3. 현재 리전을 확인한다.
```bash
aws configure get region
```
`ap-northeast-2` 가 나와야 한다. 아무것도 안 나오거나 다른 값이면 아래를 실행한다.
```bash
aws configure set region ap-northeast-2
```

4. 내 버킷 목록을 본다.
```bash
aws s3 ls
```

5. 버킷 안을 본다. (`<학번>`은 본인 학번으로 바꿀 것)
```bash
aws s3 ls s3://mlops-2026-<학번>/
```

6. 폴더 안을 본다.
```bash
aws s3 ls s3://mlops-2026-<학번>/raw/
```

7. CloudShell 안에서 테스트 파일을 하나 만든다.
```bash
echo "hello mlops from <학번>" > hello.txt
cat hello.txt
```

8. 만든 파일을 S3에 올린다. (`cp` = copy, 복사)
```bash
aws s3 cp hello.txt s3://mlops-2026-<학번>/raw/hello.txt
```
`upload: ./hello.txt to s3://...` 메시지가 나오면 성공.

9. 올라간 것을 확인한다.
```bash
aws s3 ls s3://mlops-2026-<학번>/raw/
```

10. 이번엔 반대로 내려받는다. 다른 이름으로 받아 확인한다.
```bash
aws s3 cp s3://mlops-2026-<학번>/raw/hello.txt hello_download.txt
cat hello_download.txt
```

11. 아까 콘솔로 올린 CSV도 CLI로 내려받아 앞부분을 본다.
```bash
aws s3 cp s3://mlops-2026-<학번>/raw/sample_bike.csv .
head -5 sample_bike.csv
```

12. 폴더 통째로 다루기도 해본다. (`--recursive` = 하위 전부)
```bash
mkdir -p backup
aws s3 cp s3://mlops-2026-<학번>/raw/ backup/ --recursive
ls -l backup/
```

13. 마지막으로 버킷 전체를 한 번에 훑는다.
```bash
aws s3 ls s3://mlops-2026-<학번>/ --recursive --human-readable --summarize
```
- 확인 포인트: 맨 아래에 `Total Objects: 2` (또는 3), `Total Size: ...` 가 나온다. **이 화면을 캡처**한다. (체크포인트 제출물 2번)

14. (여유 있는 학생만) 방금 만든 테스트 파일을 지워본다.
```bash
aws s3 rm s3://mlops-2026-<학번>/raw/hello.txt
aws s3 ls s3://mlops-2026-<학번>/raw/
```

**강의 스크립트 (CLI 도입 시점)**
> 방금 마우스로 한 걸 이제 명령어로 다시 합니다. "굳이 왜?" 싶으실 겁니다.
> 이유는 간단합니다. 여러분이 4주차에 모델을 100개 만들었다고 칩시다. 마우스로 100번 업로드하시겠습니까? 스크립트 한 줄이면 끝납니다.
> 그리고 더 중요한 이유 — **11주차에 자동 배포를 배웁니다.** 자동화라는 건 사람이 마우스를 안 잡는다는 뜻입니다. 컴퓨터는 마우스를 못 씁니다. 명령어만 씁니다.
> `aws s3 cp` 이 명령어 하나만 오늘 손에 익히면 됩니다. `cp`는 copy, 복사입니다. 왼쪽 걸 오른쪽으로 복사합니다. 왼쪽이 내 컴퓨터고 오른쪽이 S3면 업로드, 반대면 다운로드입니다. 그게 전부입니다.

### 팀 프로젝트 연결

- 오늘 만든 버킷 `mlops-2026-<학번>` 은 **학기 내내 여러분의 개인 작업 공간**이다.
- 3주차에 팀이 확정되면 팀 공용 버킷(`mlops-2026-team-T01` 형식)이 추가로 생기지만, **개인 버킷은 개인 체크포인트 제출 용도로 계속 유지**한다.
- `raw/` `processed/` `models/` 세 폴더 규칙은 **팀 버킷에도 그대로 적용**된다. 강사가 배포하는 모든 스크립트가 이 경로를 가정한다.
- 오늘 적어둔 **버킷 이름**은 다음 주 boto3 실습에서 코드에 그대로 들어간다. 반드시 메모.

### 순회 지도 포인트

강사·조교가 돌아다니며 확인할 것 3가지.

1. **리전이 서울인가.** 버킷 목록 화면의 리전 열을 직접 본다. 버지니아면 그 자리에서 다시 만들게 한다.
2. **버킷 이름이 규칙대로인가.** `mlops-2026-<학번>` 형식인지, 대문자나 밑줄이 섞이지 않았는지 본다.
3. **CloudShell에서 `aws s3 ls`가 실제로 실행됐는가.** 콘솔만 만지고 CLI를 건너뛰는 학생이 반드시 나온다. 화면에 명령 실행 이력이 남아 있는지 본다.

추가로 확인: 태그 3종(`Course`/`Team`/`Owner`)을 빠뜨린 학생이 많다. 비용 추적이 안 되므로 그 자리에서 채우게 한다.

### 제출물

제출처: 학습관리시스템(LMS) `1주차 체크포인트` 게시판. 파일명은 `w01_<학번>.zip` 또는 이미지 3장 개별 업로드.

| # | 제출물 | 형식 | 배점 |
|---|---|---|---|
| 1 | 본인 S3 버킷 이름을 텍스트로 기재 + 버킷 목록 화면(리전 열이 "서울"로 보이게) | 텍스트 + 스크린샷 | 0.7 |

## 부록 A. 명령어 치트시트

> **1주차 · AWS CLI (S3) 최소 명령어** — 1페이지로 뽑아 배포
> `<학번>` 자리에는 본인 학번 8자리를 넣는다. 예: `mlops-2026-20231234`

```bash
# ── 0. 나는 누구인가 / 어디에 있는가 ──────────────────
aws sts get-caller-identity          # 내 IAM 사용자 확인
aws configure get region             # 현재 리전 확인 (ap-northeast-2 여야 함)
aws configure set region ap-northeast-2   # 리전이 다를 때 고정

# ── 1. 목록 보기 (ls = list) ─────────────────────────
aws s3 ls                                             # 내 버킷 전체 목록
aws s3 ls s3://mlops-2026-<학번>/                      # 버킷 최상위
aws s3 ls s3://mlops-2026-<학번>/raw/                  # 특정 폴더 안
aws s3 ls s3://mlops-2026-<학번>/ --recursive --human-readable --summarize
                                                      # 전체를 한 번에 + 용량 합계

# ── 2. 올리기 / 내리기 (cp = copy) ────────────────────
aws s3 cp hello.txt s3://mlops-2026-<학번>/raw/hello.txt      # 업로드
aws s3 cp s3://mlops-2026-<학번>/raw/hello.txt ./             # 다운로드
aws s3 cp ./mydata/ s3://mlops-2026-<학번>/raw/ --recursive   # 폴더 통째로 업로드
aws s3 cp s3://mlops-2026-<학번>/raw/ ./backup/ --recursive   # 폴더 통째로 다운로드

# ── 3. 옮기기 / 지우기 ───────────────────────────────
aws s3 mv old.csv s3://mlops-2026-<학번>/raw/new.csv   # 이동(mv = move)
aws s3 rm s3://mlops-2026-<학번>/raw/hello.txt         # 파일 1개 삭제 (rm = remove)
aws s3 rm s3://mlops-2026-<학번>/tmp/ --recursive      # 폴더 통째로 삭제 ⚠ 주의

# ── 4. 동기화 (달라진 것만 복사) ─────────────────────
aws s3 sync ./mydata/ s3://mlops-2026-<학번>/raw/      # 로컬 → S3
aws s3 sync s3://mlops-2026-<학번>/raw/ ./mydata/      # S3 → 로컬

# ── 5. CloudShell 안에서 쓰는 리눅스 명령 (맛보기) ────
pwd            # 지금 내가 있는 폴더 경로
ls -l          # 파일 목록 (자세히)
cat hello.txt  # 파일 내용 전부 보기
head -5 a.csv  # 파일 앞 5줄만 보기
mkdir backup   # 폴더 만들기
```

**기억할 것 딱 하나**
`aws s3 cp <왼쪽> <오른쪽>` — 왼쪽 것을 오른쪽으로 복사한다.
왼쪽이 내 컴퓨터고 오른쪽이 `s3://`면 **업로드**, 반대면 **다운로드**.

## 부록 B. 용어 정리

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| MLOps | Machine Learning Operations | 모델을 노트북 밖으로 꺼내 실제로 굴리기 위한 운영 기술 전반 |
| AWS | Amazon Web Services | 아마존이 빌려주는 클라우드 컴퓨터·저장소·서비스 묶음 |
| 콘솔 (Console) | 관리 화면 | 브라우저로 접속해 마우스로 AWS를 다루는 웹 화면 |
| 리전 (Region) | 지역 | AWS 장비가 실제로 놓인 지구상 위치. **우리는 서울 `ap-northeast-2` 고정** |
| 가용영역 (AZ) | Availability Zone | 리전 안에 있는 개별 데이터센터 건물. 하나가 죽어도 나머지가 버팀 |
| 온디맨드 (On-Demand) | 쓴 만큼 과금 | 호텔방처럼 켜둔 시간만큼 초 단위로 돈이 나감 |
| 책임 공유 모델 | Shared Responsibility | AWS는 건물·전기·하드웨어, 사용자는 비밀번호·권한·포트를 책임짐 |
| IAM | Identity and Access Management | "누가 무엇을 할 수 있는가"를 관리하는 서비스. 우리 학생 계정이 여기 있음 |
| IAM 정책 (Policy) | 권한 규칙표 | 아파트 출입카드. 허용된 서비스·리소스만 열림 |
| MFA | Multi-Factor Authentication, 다단계 인증 | 비밀번호 + 1분마다 바뀌는 6자리 숫자. 계정 도용 방지 |
| S3 | Simple Storage Service | AWS의 파일 저장소. 폴더처럼 보이지만 실제로는 "객체 저장소" |
| 버킷 (Bucket) | S3의 최상위 저장 단위 | 이름이 **전 세계에서 유일**해야 함. 소문자·숫자·하이픈만 |
| 객체 (Object) | 버킷에 저장된 파일 하나 | 파일 내용 + 메타데이터를 합쳐 부르는 말 |
| S3 URI | `s3://버킷/경로` 형식 주소 | 코드와 CLI에서 파일을 가리킬 때 쓰는 표준 주소 |
| 퍼블릭 액세스 차단 | Block Public Access | 켜두면 인터넷 아무나가 내 파일을 못 봄. **항상 켜둔다** |
| CloudShell | 브라우저 안의 리눅스 터미널 | 설치 없이 바로 `aws` 명령을 칠 수 있는 검은 화면 |
| CLI | Command Line Interface | 마우스 대신 명령어로 조작하는 방식. 자동화의 전제 조건 |
| Budgets | 예산 | 월 사용액 한도와 알림을 설정하는 기능. 우리는 학생당 $10 |
| 태그 (Tag) | 리소스에 붙이는 이름표 | `Course=MLOps`, `Team=T01`, `Owner=<학번>`. 비용을 누가 썼는지 추적 |
| 인스턴스 (Instance) | 클라우드에서 빌린 서버 한 대 | 2주차부터 등장. `t3.medium`까지만 허용 |
| EBS | Elastic Block Store | 인스턴스에 붙는 하드디스크. **서버를 꺼도 요금이 계속 나감** |
| 재현성 (Reproducibility) | 같은 입력이면 같은 결과 | 원본(`raw/`)을 안 건드리고 스크립트로만 가공해야 확보됨 |
